# 16｜最关键的一层：让预测轨迹真的被执行

[教程目录](../README.md) · [上一章](15-deployment.md) · [下一章](17-homing.md)

> **学习目标：认识模型与控制的接口**
>
> 能解释受限进度、完整段和夹爪相位，理解反应速度取舍。

## 为什么30FPS模型不能直接60Hz弹出动作

50个动作按数据节拍约覆盖1.67秒；若每个60Hz周期直接弹出一个，就把轨迹加速约两倍。反过来，如果身体关节又被15°/秒限速，程序却仍按墙钟时间丢掉旧动作，模型认为已经夹好或已到盘上，身体实际还没走完，夹爪就会提前开或后续动作被跳过。

最终使用可分数的“策略进度”φ。正常60Hz每次最多推进 `30×1/60=0.5` 个策略帧，线性插值相邻目标；身体受限时再乘实际接受比例α：

```text
Δφ_proposed = min(30·min(dt,1/60), 到下一关键点的距离)
q_proposed = interpolate(trajectory, φ + Δφ_proposed)
q_sent = q_previous + α·(q_proposed − q_previous)
φ_next = φ + α·Δφ_proposed
```

α由身体五关节共同决定，满足单周期速度限制和相对当前反馈5°范围。共同α保留这一小段的关节比例；不独立裁剪每个身体关节后还假装策略已经按原速前进。目标进度属于命令轨迹接受程度，不等于精准测量了末端真实路径。

## Guard 做什么

先验证有限数值、坐标和绝对范围，再沿前一发送目标到新目标求共同α。60Hz时15°/秒意味着每身体关节目标变化最多0.25°；同时新目标相对实测反馈不得超过5°。反馈超过35ms刷新，编码跳变和异常进入保持。原3秒启动渐入和工作边界保留；驱动内 `max_relative_target=None` 避免重复读反馈和重复限幅，最终仍调用原生目标写入。

```python
# 当前实现的关键接口，身体与夹爪分开处理
values, reached, scale = coordinated_target(
    previous_body, requested_body, observed_body, caps_body, dt)
sent_body = values
sent_gripper = clip(queue.gripper_target(scale), gripper_low, gripper_high)
queue.advance(scale)
```

## 为什么夹爪不能决定整臂时间

示范可能在夹住螺母后继续给更闭合的位置目标。这在位置控制里是合理的夹持意图，但反馈受物体阻挡，不会到达空载目标。若把六维“全部到位”当继续条件，或把夹爪误差也参与共同减速，机械臂会在抓住后停止搬运。

v7的共同α只用五个身体关节计算；夹爪从**相同已接受策略相位**取值并限制到校准范围，不加独立2pp反馈限幅、15pp/秒限速、专用平滑或接触门控。这样既不因夹爪受阻卡住整臂，也不让夹爪走到身体尚未到达的未来时刻。

这仍然是位置目标，不能保证自适应夹持力。底层电机原有电流/过载/力矩配置保留，未因去掉上层开合限制就去掉电气保护；本轮也没有安装力传感器。

## 15帧重规划为什么丢掉松爪

历史日志中，频繁新预测覆盖旧预测，实际长期只消费预测前段；原始审计最大使用源索引29，11个接入块的开爪发生在当时未执行的后半段。因此“模型预测了后续开爪”和“执行器真的执行到开爪”是两件事。离线无法把所有提前掉落都归因于队列，摩擦和对位仍会影响，但该截断是有日志证据的控制问题。

当前 `execution_horizon=50`：新预测可异步更新到pending，当前已承诺段走完剩余关键帧后再换段，直到源索引49。新块用 `current_progress − request_progress` 跳过已经实际消费的部分，保留分数偏移下的最后关键帧。过旧结果不接入，避免补执行陈旧动作。

身体用7帧三角权重 `(1,2,3,4,3,2,1)/16` 平滑，换段前5帧做过渡；夹爪不参与这些平滑。执行完整段会延长对新观察反应的时间，是本任务当前版本的取舍，并不意味着所有任务都应无条件完整执行50步。Q/R、故障与看门狗仍可立即中断。

### 同样预测50步，实际消费到哪里才重要

```text
早期每15帧覆盖：0…14 → 新块0…14 → 新块0…14 → …
                若松爪出现在后半段，它会持续没有机会执行

当前完整承诺段：0 → 0.5 → 1 → … → 49 → 接入更新预测的剩余段
                身体受限时：每轮只推进被接受的策略进度
```

上面松爪位于“后半段”只是机制示意，并非声称本模型固定第42帧开爪。队列实际用可分数相位：

```text
正常60Hz：proposed Δphase ≤30×1/60 =0.5
若身体只接受 α=0.5：accepted Δphase ≤0.25
夹爪与身体都从同一个accepted phase取目标
```

身体工作边界和单步限幅保留；夹爪仅限制活动范围，不让受阻夹爪冻结整个身体进度。相位是软件目标的接受程度，不是电机或末端物理运动完成证明。

## 再用一组数字，把夹爪相位与分数衔接算到底

在一个教学小段中，假设拟推进0.5帧时夹爪会由52变成48个百分点，身体只接受α=0.125，则实际推进0.0625帧，夹爪应取52+(48−52)×0.125=51.5。仍发送48就让夹爪走到了身体尚未到达的未来时刻。52/48和α均为教学假设，不是实机预测，也不意味着新增夹爪限速。

异步请求时的进度若为100，结果真正安装时为106.5，就从新块跳过已经消费的6.5帧。采样将经过6.5、7.5…48.5，并保留最后源索引49；简单截成整数长度可能丢掉最后一个目标。这个数字例子对应队列代码的分数offset逻辑，说明“保留最终关键帧”为什么值得单独测试。

## 看门狗与退出

过1秒的预测不安装；相机超过0.5秒、推理/新鲜观察超过1.5秒失联时保持，身体3秒未推进一个策略帧也保持。Q保持当前姿势，R进入主从复位，S/F是人工结果标签；X/Ctrl+C退出前要托稳，程序释放并回读力矩。45秒模型阶段上限不含归位等待。没有障碍物规划或自动碰撞检测。


## 手算一次限速后的策略进度

假设当前策略相位φ=10，下一控制周期dt=1/60s。按30FPS，原拟推进0.5帧；身体五关节中最严格的一维只接受这段变化的α=0.4，则真正接受的策略增量为0.2帧，相位走到10.2。夹爪也取10.2处插值目标。若错误地让夹爪直接取10.5，它就提前了0.3个策略帧；连续出现会把搬运与松爪的相对时序打乱。这里φ和α是解释算法的假设，实际每周期由Guard和日志确定。

```text
 每周期身体目标速度上限 = 15°/s × 1/60s = 0.25°
 相对反馈范围           = 当前实测角度 ±5°
 拟推进Δφ               = 30×1/60 = 0.5帧
 实际接受Δφ             = 0.5×0.4 = 0.2帧
```

0.25°是相邻发送目标的速度限制，5°是发送目标相对当前反馈的误差范围，不能把5°当成每周期都可以跳5°。进度对齐让六维动作保持共同的任务时间，电机真正到达仍要靠反馈检验。
