# 07｜验收、划分与未来动作窗口

[教程目录](../README.md) · [上一章](06-data-engineering.md) · [下一章](08-batch-lab.md)

> **学习目标：构造无泄漏的训练样本**
>
> 能解释整条划分、训练统计与末尾padding。

## 为什么先验收再训练

数值检查覆盖50条29570帧的状态、实际动作、索引、时间与提交状态；所有视频完整解码，官方读取器对每条首、中、末共150处读取图像、状态及50步动作窗口。原件验收前后SHA-256一致。

视觉上按全长2FPS分镜审阅2039张、94页，对11条相关片段加密至5FPS。50条均可确认放盘，37条直接通过、13条带轻微备注；无强制剔除。备注包含对位较慢、成功后静止尾段较长、成功后后撤导致目标出画。本轮训练**没有裁剪尾段**，也没有偷偷删改原始episode。它不是逐帧30FPS人工视觉审阅。

## 划分单位是整条episode

验证ID固定为 `[4, 14, 24, 35, 48]`，每10条记录中保留1条；其他45条训练。官方划分返回后，封装再次断言名单和交集，训练每个batch继续检查episode ID属于训练集。随机种子1000不代表随机拆帧；整条隔离防止相邻画面同时出现在训练与验证。

**实际划分：** 验证episode为 `[4, 14, 24, 35, 48]`，其余45条用于训练。整条episode只属于一个集合，原50条保留。

| episode22锚点 | 50步窗口有效索引 | 有效步 | 重复末帧补齐步 |
| --- | --- | --- | --- |
| 245 | 245…294 | 50 | 0 |
| 480 | 480…489 | 10 | 40 |
| 489 | 489 | 1 | 49 |

补齐保持张量形状；`action_is_pad`将这些越界位置排除出loss，不会跨入下一条episode。它不补偿真实时间抖动。

## 一个训练样本不是整段视频

以段内帧 `t` 为锚点，当前配置 `n_obs_steps=1`：取这一帧的图像、当前6维状态和任务文本；监督标签为 `action[t:t+50]`。配置的动作相对索引为 `0…49`，包含锚点动作，并非从 `t+1` 开始。50步标称约1.67秒，但不代表模型一次预测整条十几秒的任务。

若t靠近末尾，索引被夹到本episode的最后一帧，同时生成 `action_is_pad=True`。例如490帧的episode22，在t=480时，只有480…489这10步有效，剩余40步复制末动作作形状补齐，并从损失中排除。不能读取到下一条episode的复位或新任务。

```python
# LeRobot 0.6.1 DatasetReader._get_query_indices：等价简写
indices = [max(ep_start, min(ep_end - 1, idx + d)) for d in deltas]
is_pad = [(idx + d < ep_start) or (idx + d >= ep_end) for d in deltas]
```

## 归一化只看45条训练数据

封装只读Parquet的状态和动作列，筛选训练episode，用float64计算各维均值、总体标准差（ddof=0）等统计。替换内存中的训练元信息统计，把结果另存日志；不改原数据 `meta/stats.json`。验证与部署复用随检查点保存的同一套统计。

```text
state_norm[j]  = (state[j]  - state_mean[j])  / (state_std[j]  + ε)
action_norm[j] = (action[j] - action_mean[j]) / (action_std[j] + ε)
ε = 1e-8
```

状态和动作各有自己的均值、标准差。例如腕旋转的变化幅度远小于肩抬升，标准化让小幅通道也能参与学习。推理输出必须用**动作**统计反归一化，不能误用状态统计。图像的策略归一化类型为IDENTITY，但读取器的0–255转0–1、模型内转−1–1仍然执行，不能把IDENTITY理解为“图像完全不处理”。
