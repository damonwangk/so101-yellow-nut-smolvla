# 06｜数据工程师怎样判断一条示范是否可信

[教程目录](../README.md) · [上一章](05-format.md) · [下一章](07-dataset.md)

> **学习目标：做有依据的数据判断**
>
> 能分清硬错误、任务失败、软备注和覆盖不足。

## 先学会回答：我们在教模型什么

数据工程师首先写清楚“样本代表什么”，再讨论文件能否打开。本任务的学习目标是：看到腕部图像、当前从臂位置和一句任务指令，预测接下来的一段从臂关节目标，让黄色螺母最终留在棕色盘内。画面清晰只是这个目标的一部分；图像关联错了动作，即使每个文件都能播放，训练仍会把错误的关系学进去。

可以把一帧样本读成一句带证据的话：“在这个场景、这个关节状态下，操作员通过实际控制链路给从臂发送了这些目标；同一条示范的后续目标构成监督轨迹。”我们要保存的不只是看起来成功的视频，而是这句话的各个部分及其对应关系。

本项目的数据验收采用四层判断。它们逐层增加证据，不会因为最后视频放盘成功，就免除前面的数值与时序检查。

| 层次 | 要回答的问题 | 不合格会怎样 | 本项目怎样查 |
|---|---|---|---|
| 文件与结构 | 这一条是否完整、可读，字段、维度和索引是否成立？ | 训练报错，或者把错位行当成标签 | 50条元信息、提交状态、29570行数值与全部视频解码；官方读取器150处抽查 |
| 测量与对应 | 图像、实测状态、发送目标是否来自同一段操作，时间和坐标语义是否明确？ | 模型学成“看到现在却模仿别的时刻”，或把主臂坐标当从臂目标 | JSONL与Parquet逐行核对；主机时间与坐标映射来源检查 |
| 行为与任务 | 示例是否包含接近、夹取、搬运、释放以及可辨认结果？ | 数据只教会抓起，没教会怎样收尾；失败动作与成功标签冲突 | 全长2 FPS人工分镜审阅，11条相关片段加密至5 FPS |
| 分布与用途 | 数据是否覆盖将要测试的初态、位置、朝向和视觉条件？ | 数据内很像，换个位置便失败 | 当前记录只能支持相近桌面条件；未量化位置均匀性，不宣称跨环境泛化 |

**“适合本次训练”是相对于任务和使用条件的结论。** 同一条慢速纠偏示范可能有助于学习对位，也可能让追求节拍的生产任务学得太慢；是否保留，要结合目的、抽样方式和后续验证判断。

## 一条真实记录：为什么 state 和 action 不能互相代替

本项目六个通道固定为 `shoulder_pan、shoulder_lift、elbow_flex、wrist_flex、wrist_roll、gripper`。前五个单位为度，夹爪为校准后的开度百分点。第22条第245帧，标称时间约8.167秒，保存的是以下真实数值，表中仅为阅读而四舍五入：

| 通道 | 实测 state | 实际发送 action | action−state |
|---|---:|---:|---:|
| shoulder_pan | 2.989 | 3.033 | +0.044° |
| shoulder_lift | −38.418 | −38.681 | −0.264° |
| elbow_flex | −17.363 | −21.495 | −4.132° |
| wrist_flex | 53.978 | 54.066 | +0.088° |
| wrist_roll | −1.363 | −1.451 | −0.088° |
| gripper | 35.123 | 33.123 | −2.000个百分点 |

`state` 回答“读到了哪里”，`action` 回答“这一控制周期实际发送了什么目标”。电机还在运动、夹住物体或受到负载时，二者不同很正常。上表的夹爪目标比当前开度更小，表示还在请求闭合；它并不表示已经测到了某个夹持力。不能因为位置差不为零就判错，也不能把 `state` 复制成 `action` 来消除差值。

下面是**读取现有真实样例的只读练习**，不是连接机械臂的代码。网页中的完整浮点数来自 `assets/真实数据样例.json`。

```python
import json
from pathlib import Path

data = json.loads(Path("实施教程/assets/真实数据样例.json").read_text())
row = next(x for x in data["episode22"]["samples"] if x["frame_index"] == 245)
print(row["episode_index"], row["frame_index"], round(row["timestamp"], 3))
print([round(a - s, 3) for s, a in zip(row["observation.state"], row["action"])])
```

```text
22 245 8.167
[0.044, -0.264, -4.132, 0.088, -0.088, -2.0]
```

这里的 `action` 必须沿着真实控制链取值。采集代码保留了 `leader_action → mapped_target → bounded_target → requested_action → sent_action` 的中间记录，写入训练数据的是从臂驱动实际发送调用返回的 `sent_action`，不是未经映射的主臂读数，也不是限幅前“原本想发”的目标。这保证模型学到的动作与当时采用的执行语义一致；返回值仍然是软件发送目标，不能进一步解释成电机已经达到目标或物体已经被夹牢。[查看实际发送记录代码](../code/project/record-so101.py#L828)

**教学反例，非本数据集实际发现：** 如果一批数据前半使用角度、后半误用弧度，而字段名和维度都一样，文件检查可能通过，但同一画面会对应两套完全不同的数值。解决方式是先隔离该批次、核对校准版本与单位来源，在可追溯副本上转换后重新验收；不能依赖“模型应该能自己适应”。同理，主从坐标偏移只能施加在对应链路，不能对已经是从臂坐标的模型动作再补偿一次。

## 同步不是“行号相同”：先看来源事件再判断误差

视频第100帧与60Hz控制第100轮不能按序号直接拼接。当前程序以图像接收时间选择最近在先的反馈，并取该反馈同软件周期的发送目标；`alignment.jsonl`保留真实主机时间，LeRobot训练仍用`frame_index/30`规则轴。它是可追溯的近似关联，没有证明曝光级硬同步，也没有显式进入网络做延迟补偿。

[第04章的真实时间轴](04-timing.md)逐帧展示29570行的分布、第22条第245帧及发送发生在图像之后的第12帧，并解释哪些偏差会影响抓取。验收时应分开检查字段一致性、误差分布和关键接触阶段；平均FPS正常不能替代后两项。

## 为什么37条通过、13条备注仍然都能训练

判定质量时先问“问题发生在哪个阶段、是否破坏了任务证据和学习标签”，不要看见非理想行为就删。以下都来自原验收报告，时间是分镜审阅的约值。

| 真实条目与现象 | 判定依据 | 对学习可能的影响 | 本轮处置 |
|---|---|---|---|
| 0、1、10：前段对位约15.5–16秒，较慢 | 仍包含完整接近与抓起；分别约24.5、23.5、22.5秒释放入盘，结果可见 | 有纠偏经验，也让等待/微调动作占据更多采样位置；不能仅凭慢认定无效 | 软备注，完整保留 |
| 3：约20秒放盘，尾部又保持约7.7秒 | 已完成释放且成功结果稳定；冗余主要发生在结束后 | 较长静止尾段增加“保持不动”样本比例，可能降低训练效率；不证明它必然导致部署停顿 | 软备注；报告给出未来副本可保留至22秒，本轮未裁剪 |
| 2：约22.5秒释放；27秒后裁切/出画 | 结果在出画前已清楚可见数秒，关键释放没有被遮掉 | 尾段提供的信息变少；不应据后撤画面反推“抓放失败” | 软备注；可选副本截止26.8秒，本轮保留原条 |
| 18：16.5秒释放；19.9秒起间歇裁切 | 已有成功结果，再发生后撤出画 | 与条2类似，是尾段可见性问题 | 软备注；可选19.7秒，本轮未应用 |
| 30：15秒释放；18.5秒后裁切并出画 | 放盘与结果此前清楚 | 模型可能学到不必要的大后撤，需要在目标节拍与终止定义中评估 | 软备注；可选18.3秒，本轮未应用 |
| 31、34、39、40、43、44：成功后边缘裁切/出画 | 关键结果已有证据；详表分别保留约时间点 | 同类尾段问题，不是六种新的失败 | 软备注，保留并可按标签检索 |

因此，**13条不是13条坏数据，更不是13条抓取失败**。它们由3条慢对位、1条长静止尾段、9条成功后裁切/出画构成。本轮没有必须排除的条目，训练使用50条可用示范再按整条划为45/5，也没有应用表中的可选裁剪时间。

质量标签应与事实分开：`observed: 放盘成功后出画`、`decision: 可用但备注`、`possible_effect: 尾段信息较少`、`action_taken: 原件未改`。把推测写成“模型会失败”会越过证据；把事实压成一个“坏”标签又会丢失后续分析价值。

## 硬错误与软备注，如何做处置决定

可以按以下顺序判断。**隔离**是暂时不进入训练，不等于删除原文件；只要来源还在，就可以修复派生副本后重新验收。

1. **是否无法解释这条训练标签？** 例如字段缺失、NaN/Inf、视频损坏、状态/动作维度错、单位或坐标来源不明、窗口跨episode。这类问题优先隔离，不能靠“看起来成功”通融。
2. **是否与要学习的任务矛盾？** 例如任务要求放入盘中，视频却掉落在桌面、没有任何释放结果，而仍标成成功示范。若没有明确的失败学习/恢复训练设计，应先隔离并查证标签。
3. **是否只是任务完成后的冗余或动作风格差异？** 若关键流程与结果成立，先软备注保留；在有版本的训练副本中比较裁剪或采样方案。
4. **是否缺少证据，暂时无法判断？** 标成待复核，比强行通过或删掉更有价值；回看更密集视频、原时序日志或采集记录。

以上第1、2项的例子是**教学反例，不是本次50条中实际查出的错误**。本数据集验收结论中没有强制剔除项。

把这个流程用于实际工作时，每个标记至少记录 `episode_id、证据时间/帧、问题类型、事实、决策、审核方式、版本`。只写“质量差”无法复核，也无法分析模型错在何处。本项目的 `quality_labels.json`、`episodes_review.csv`、技术结果和前后哈希清单分别承担这些角色；可选尾段截止只是方案，必须另写应用记录，才能声称训练用过裁剪数据。

## 每项检查解决什么，又漏掉什么

| 已完成检查 | 它提供的证据 | 它不能独自证明 |
|---|---|---|
| 所有29570帧视频解码成功、尺寸与计数一致 | 编码可读，保存帧数能对上 | 每帧都符合任务语义、无运动模糊、夹持牢靠 |
| 无近黑帧、无相邻RGB完全相同帧 | 排除本次采用规则能发现的黑图/完全重复异常 | 相似但不完全相同的卡顿、遮挡、所有曝光问题 |
| 全量数值、索引和JSONL对应检查 | 数据内容、来源记录与字段关系一致，未见NaN/Inf与所查跳变 | 电机达到每个目标、传感器物理精度或夹持力 |
| 官方读取器每条首/中/末150处读样本 | 典型位置能拼出图像、状态和50步窗口，尾部补齐与段界成立 | 只靠这150次读样本就覆盖所有可能读取路径 |
| 全长2 FPS人工分镜与11条片段5 FPS复核 | 在0.5秒/0.2秒粒度观察主要任务阶段与结果 | 30 FPS逐帧人工审阅；两张分镜之间没有短暂滑落/碰撞 |
| 主机时间单调、间隔与漂移检查 | 主机侧关联和节奏合理 | 硬件曝光与电机严格同步 |
| 原始539个文件路径前后SHA-256一致 | 验收期间原件内容没有改变 | 文件在采集前就正确，或模型能泛化 |

工程判断需要组合证据。比如“数值有效、视频可读、人工看到盘内结果、任务窗口未跨段”共同支持本次成功示范可用；任何一项都不能单独替代其他项。细粒度接触质量若成为下一阶段主要问题，就要提高那部分审阅与测量的分辨率，而不是笼统地把既有验收叫作“全部逐帧看过”。

## 统计的单位，决定模型经常看见什么

这里有50条任务演示、29570帧，却没有29570种独立场景。相邻图像、关节状态和未来50步窗口高度相似。若当前加载器按有效帧抽取锚点，较长episode通常提供更多候选样本；条0的873帧约为条31的400帧的2.18倍。长对位和长尾段也随之得到更多监督位置。

因此，数据工程师既看“条数”，也看每阶段的时长与覆盖：接近、闭合、提起、搬运、松开、结果保持各占多少；不同物体位置、朝向、初始姿态出现多少；相机、光照和标定版本是否变化。当前未给全部帧标注这些阶段，也未量化五位置各10条的均匀性，不能从“50条”直接推出均匀覆盖。

对下一轮数据，先定义希望覆盖的工作区域与朝向，再给每条写入分组标签；保留偶发纠偏但避免大量无目的等待。若测试失败集中在某个位置或角度，补充那部分成功/恢复示范，再建立隔离评估集，通常比无差别加录同一位置更有针对性。不要只收集最容易的一种初态，却用它宣称所有位置都会抓。

起始姿态差异同样是分布的一部分。本轮没有因初态不同而删除示范；部署从45条训练起点中选了真实代表点episode22第0帧归位，减少当前测试变量。固定归位是部署设计，不会使训练集自动获得新位置、新摩擦或新光照的能力。

## 为什么按整条划分，而且统计只能看训练集

相邻帧非常像；一个50步动作窗口还会与下一个窗口共享49步。随机把帧拆成训练/验证，会让同一次演示的近似画面和大段标签出现在两边，验证loss看起来很好，却没有回答“对没见过的示范是否有效”。

本轮5条验证集为 `[4,14,24,35,48]`，共2848帧，其余45条26722帧用于训练。整个episode只属于一边，窗口不跨段。状态/动作均值与标准差只由这45条计算，验证和部署复用相同统计；验证数据不能在归一化阶段提前告诉训练流程它的分布。

这仍主要是**相近采集条件下的保留示范验证**。如果同一桌面、同一天、同一物体都落在两边，它不能代表对新桌面、新相机位置、新物体的评估。下一层评估应按所声称的能力设计分组：检验新位置，就保留位置组；检验跨天稳定性，就保留日期/会话；检验换相机，就保留相机配置。划分的边界要对应应用中的变化，而不只是为了凑一个比例。

## 一个数据集，应当能追溯到训练与现场

最小可追溯链是 `原始采集与时序日志 → 独立QC标签 → 可用名单/划分 → 训练统计 → run配置与检查点 → 部署代码/校准 → 实机评估`。模型文件本身无法告诉我们是否误用了验证统计、删掉了什么尾段、是否施加了错误坐标补偿。

本项目保留原始 `lerobot/、episodes/、sessions/`，QC另存目录；校验539个原件路径，发布标准数据153个文件；训练记录 `split.json`、训练专用统计、日志与检查点；部署另存推理请求图像和控制事件。它们回答不同问题，不能把推理日志自动当成新的成功示范，也不能把手机拍的成功视频自动算进原50条训练数据。

如果要裁剪、重采样或重新标注，先生成带版本的副本与变换清单，并写清输入哈希、规则、输出哈希和适用条目。保留原件的意义不是“舍不得删”，而是让之后发现的学习问题有机会被重新解释、复现与修正。

<summary>查看答案与证据</summary>

**答案：C。** 本项目用主机图像接收时间选择最近的前置控制观测，并保存读写时刻，支持主机侧关联一致性。标称30 FPS不是曝光时间测量，肉眼观察也不能证明硬件同步。快速接触研究还需曝光时间戳或硬件同步等证据。

来源：record-so101.py：read_camera_frame / select_control_sample / EpisodeWriter；验收报告时间边界；类型：实际实现与证据边界。

</details>

**问题4：有50条示范。为了让训练和验证都覆盖所有场景，能否把同一episode的奇数帧训练、偶数帧验证？**

- **A.** 可以，帧号不一样就没有泄漏
- **B.** 不应这样做；相邻图像与50步窗口高度重叠，应至少整条episode隔离
- **C.** 可以，只要训练集和验证集文件放在不同文件夹

<details>
<summary>查看答案与证据</summary>

**答案：B。** 相邻锚点可能共享49/50的动作标签，又看到近似画面。按帧拆分会让验证虚高。当前验证为整条4、14、24、35、48；若要检验未见位置，还应按位置组设计独立测试，而不只是改变文件路径。

来源：机械臂项目记录.md：6.1；训练split.json记录；类型：实际划分与数据工程原则。

**问题5：【真实样例】episode 22第245帧夹爪state约35.123，发送action约33.123。这个差值应怎样解释？**

- **A.** 数据错了，应把action覆盖成state
- **B.** 它证明夹爪输出了2单位夹持力
- **C.** 目标还在请求进一步闭合；状态与目标可以不同，现有位置日志不能直接测夹持力

<details>
<summary>查看答案与证据</summary>

**答案：C。** state是实测位置，action是实际发送目标，差约−2.000个开度百分点。响应滞后或物体阻挡都可使位置未达到目标。不能把位置差直接换成力，也不能用状态替换真实动作标签。

来源：assets/真实数据样例.json：episode22 / frame245；类型：真实数值样例。

</details>

**问题6：【教学反例，本轮未发现】一条视频看似完成放盘，但Parquet中有NaN，或action单位无法确认。怎样处理？**

- **A.** 先隔离出训练名单，保留原件并追查来源；修复派生副本后重新验收
- **B.** 成功视频优先，直接训练
- **C.** 删除视频和日志，避免留下坏数据

<details>
<summary>查看答案与证据</summary>

**答案：A。** 无法解释的数值标签会污染监督或使训练异常，属于硬错误/证据缺失，不能由成功画面豁免。隔离不等于删除，修复必须能追溯规则、输入与输出。此题为反例，不代表本次50条存在这些错误。

来源：本章硬错误处置原则；非实际坏样本报告；类型：明确标记的教学反例。

</details>

**问题7：本次全部29570帧都成功解码，并做了全长2 FPS分镜人工审阅及11条相关片段5 FPS复核。最准确的表述是什么？**

- **A.** 已用30 FPS逐帧人工看过每条视频
- **B.** 解码覆盖全部保存帧；人工内容审阅主要是0.5秒粒度，复核片段0.2秒粒度，可能漏过更短事件
- **C.** 只要解码通过，就不用再检查任务结果

<details>
<summary>查看答案与证据</summary>

**答案：B。** 机器解码检查编码可读，人工审阅判断内容，二者的覆盖和目的不同。2 FPS意味着相邻分镜约0.5秒，5 FPS约0.2秒；不能把抽样审阅升级为30 FPS逐帧视觉判断。

来源：数据验收报告.md：检查方法与通过项；类型：真实验收方法与限制。

</details>

来源：机械臂项目记录.md：6.1；training_normalization_stats.json；类型：实际训练方案与防泄漏原则。
