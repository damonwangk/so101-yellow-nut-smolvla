# 05｜LeRobot v3 文件里究竟是什么

[教程目录](../README.md) · [上一章](04-timing.md) · [下一章](06-data-engineering.md)

> **学习目标：学会读数据目录**
>
> 从元信息追到正确的数值行、视频与episode边界。

正式数据已经是 **LeRobotDataset v3.0**，包含数值、视频和元信息。不是只有原始MP4，也不是RLDS。我们的本次写入策略恰好形成每条一份Parquet和视频；v3格式本身支持更一般的文件分块，不要求永远“一条一文件”。

```text
formal/lerobot/
  data/chunk-000/file-000.parquet … file-049.parquet
  videos/observation.images.wrist_camera/chunk-000/
    file-000.mp4 … file-049.mp4
  meta/
    info.json
    stats.json
    tasks.parquet
    episodes/chunk-000/file-000.parquet … file-049.parquet
```

标准训练目录153个文件、201730299字节；原正式目录还包含逐条查看视图、会话和QC等，共539个文件路径。发布标准数据集时保留153个原生文件；Windows完整原始目录继续保留。

| 字段 | 作用 |
|---|---|
| `observation.images.wrist_camera` | 根据视频位置解码的单帧RGB |
| `observation.state` | 当前从臂6维实测位置 |
| `action` | 当帧关联的6维实际发送目标 |
| `task_index` / `task` | 从任务表恢复统一英文指令 |
| `episode_index` / `frame_index` | 任务段与段内帧序号 |
| `index` / `timestamp` | 全局索引与标称段内时间 |
| `action_is_pad` | 读取未来动作窗口时产生的越界掩码，不是另一个电机标签 |

`timestamp = frame_index / 30`，给模型提供一致的标称动作节拍。`alignment.jsonl` 另存相机主机接收、从臂反馈和发送动作时间。验收证明这些记录相互一致；没有硬件触发曝光时间测量，不能称为相机曝光与电机严格硬同步。

## 真实样例：episode22

第22条共490帧。第0帧实测状态约为 `[-5.275, -77.099, -0.484, 87.560, -1.890, 52.147]`；实际动作约为 `[-5.407, -77.802, 0.044, 87.824, -1.538, 52.459]`。其不同之处正是“观测”和“控制目标”的区别。离线交互包可切换首帧、中段和末尾数值，并查看同帧起点参考图。

## 把存储层与训练接口分开

Parquet保存数值列，适合按列检查和筛选；MP4压缩图像，减少存储压力；metadata负责把它们重新关联。训练代码拿到的是Python字典和Tensor，并不需要把MP4整段转成数千张图片再全部塞进显卡。两层之间的桥是Dataset reader。文件小不等于标签正确，reader能打开也不等于任务成功；下面的数据工程章节会按不同证据逐层判断。

不能。这个数据集碰巧每条一文件；v3可将多条放进共享文件，episode范围必须由元信息解析。
